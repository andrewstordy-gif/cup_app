## Design gate and acceptance criteria

1. Author first documents exact schema additions, current content/revision/coverage identity, semantic-change detection, completion eligibility, actor/restart/corruption/transaction rules, migration fixtures and treatment of prior unversioned completion evidence. Independent reviewer must approve before runtime edits. No product-policy invention; ambiguous legacy evidence is preserved and fails closed for new reveal/authority, not silently certified.
2. Additive, idempotent migration supports actual schema shapes and partially applied columns, not only PRAGMA user_version4. No destructive table/drop/response rewrite. Atomic new foundation initialization/backfill with failures leaving original rows recoverable and no partial read cutover; migration errors prevent editing. Preserve exact original data including raw response/result JSON, historical policies, adoption source/token, identity and timestamps; no AsyncStorage migration.
3. Current completion is tied to exact saved score/note content and local membership coverage, not Boolean row existence. Changes atomically invalidate current completion/reveal, preserve historical evidence/ever-completed setup latch, return IN PROGRESS and survive restart. No-op Save, reading and unsaved edits do not invalidate. A later recompletion records new current evidence without erasing original completion timestamps/history. Corrupt state fails closed, never reconstructs privilege from caller booleans.
4. First explicit saved score/note starts tasting. Recovery/autosave must not be mistaken for explicit Save; assess existing Legacy autosave paths and gate rather than accidentally start/complete/reveal from recovery. Preserve acknowledged drafts as data. Empty creator Save stays DRAFT/new; saved assigned setup remains PENDING. Durable started history prevents temporary DRAFT/empty roster restoring preparation identity. No required-note policy added.
5. Current actor and trusted pin/mode/count/revision must be checked inside transaction and before acknowledgement. Foreign/unattributed streams remain protected; historical globally complete/unknown pins stay read-only unless explicitly supported. Cross-session/stale context/callback/competing writes cannot qualify or reveal the wrong revision.
6. Existing scanned-sample import updates local coverage only for an actual new sample, invalidates prior current completion, preserves existing saved results/assigned numbers and never expands unseen advertised roster. Existing rescan opens without duplication or automatic reopen. Membership-removal UI/commands remain next-stage work; state primitives must handle/test empty coverage safely without authorising removal themselves.
7. Tests cover fresh and older/partial-schema startup, repeated migration, injected rollback/restart, old completed89.5 preservation, unknown/foreign/corrupt provenance, unchanged original completion rows and score pins, CVA/Legacy saved edits/notes/no-op, completion then edit/recomplete, no empty completion, rescan vs new membership, stale/actor races and DTO privacy. All retained applicable checks run exact final source; superseded assertions updated to specification not deleted wholesale.
8. Independent architecture/security/privacy/QA and separate UX/source review; exact committed-source iOS export in transient isolated staging without changing live Metro. Software evidence distinct from pending actual phone/native/physical tests. No main integration or phone release in this task.
