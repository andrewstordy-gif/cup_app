## Acceptance criteria

- Every supported, exactly pinned Session card presents its selected form in readable text, distinct from Session type and status. The names follow the approved two-form terminology; do not infer Legacy from the Session title or type.
- Derive the label from persisted Session form identity, with the bundled registry or established identity helper where suitable. An unpinned, historical, mismatched, or unsupported Session must display a neutral **Older or unsupported form** (or equally clear wording), never silently default to CVA or Legacy. The card remains available for its existing read-only/unsupported handling; this task does not re-pin it.
- Preserve existing order, search, navigation, deletion confirmation, status badges, and Session type display. Search may include the form label as a small, tested convenience, but no other search redesign is in scope.
- The form text is visible and included in the card's accessible name without relying on colour alone. It fits a narrow iPhone width with long Session titles and dynamic text; use established typography and spacing tokens, not a new large badge or layout pattern.
- Focused tests cover CVA, Legacy, unsupported/historical/missing identity, long title/narrow layout at source or render-test level, and existing navigation/search regression. Build/bundle validation and actual phone visual/accessibility checks are recorded separately; no physical NFC claim is needed for this presentation-only task.
