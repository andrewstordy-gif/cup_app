1. New editable completion applies only to stored R1-114 enrolled locked creator
   active target owned by current actor, supported pins and valid current R1-116
   completion (or qualified predecessor all-active completion). Keep DRAFT, grey,
   foreign/unattributed, unsupported/historical, old unmarked/participant/QuickStart
   behavior unchanged. Existing accepted session works without recreation/reset.
2. Opening completed active form shows original saved values and permitted coffee
   identity; no status/revision/history/score/code changes just from read/open.
   Existing score/notes controls editable through repository-proven access; setup
   remains locked. No new form completion button or alternate state badge.
3. Ordinary local typing is unsaved. Legacy recovery drafts may persist only as
   recovery, without changing committed results/completion/reveal. Existing
   Stay/Leave discard restores original saved values, drops only the relevant
   unsaved recovery and leaves COMPLETE/reveal/evidence intact. Failed Save does
   not discard edits or partially reopen; opening recovery is not an explicit Save.
4. Explicit Save compares current saved semantic response with submitted frozen
   response under actor/target/revision/identity/count/generation/current-completion
   guards in one exclusive transaction. Identical/no-op or changed-then-restored
   response keeps COMPLETE and creates no extra revision/completion. Changed score
   or notes (notes-only included) commits target normally, reopens IN PROGRESS if
   saved ratings remain else PENDING, re-hides all relevant Blind identity, retains
   setup/history/other targets/grey cards/code/immutable completion evidence. Never
   automatically recompletes, including changed-then-later-restored saved values.
5. Membership/profiles/score changes invalidate stale saves/acknowledgements;
   removed/reactivated target stale form/recovery cannot resurrect results. Preserve
   R1-115 generation fences and Legacy queue ordering. Recompletion requires press
   COMPLETE SESSION and current active completeness. No tag write/scan/upload.
6. Real SQLite both forms plus actual get/edit/Save/Stay/Leave/queue callbacks:

## Design / handoff / review / DoD

PM approved three runtime files: sessionRepository, CanonicalCvaScreen and
LegacyCuppingScreen. Repository proves the enrolled creator/active owned target
and qualified completion and exposes separate canEditCompleted access while
retaining sessionComplete metadata. All enrolled Save/recovery commands require
the captured tasting context token. Existing revision/fingerprint/generation,
identity/count/pin and actor checks remain. Changed Save reopens inside the same
exclusive transaction as committed results/history/revision; no-op preserves
COMPLETE/revision/evidence (Legacy may clear only matching own recovery). The
canonical store, localTastingState, schema, NFC, navigation and calculators are
unchanged. Existing standalone Complete rejection is not bypassed globally.

Legacy recovery does not reopen. Own successful queued Save may advance only its
same-load/generation token lineage, preserving typing during Save. Immutable load
epochs reject old commands and retained handlers even when reloading produces an
identical backend token. Scoped Leave freezes further enqueue, drains its captured
queue, and compares current fingerprint/token/generation plus exact opaque owned
recovery-row token before discard. Final acknowledgement checks actor/selection
and row absence; it never fetches a newer row token to clear or re-deletes a late
row. Canonical edit/Save/Back/Alert callbacks bind immutable load epochs too.

New completed-tasting-edit-check uses real SQLite and actual AST-extracted form
load/edit/Save/Stay/Leave/queue callbacks. It passes both forms: read nonmutation,
no-op/reverted unsaved, notes and scores, last-rating clear Pending/history,
recovery/discard, newer-row and postcommit actor/membership/reinsertion races,
SQL rollback, same-token reload/unmount stale handlers, own-Save queue lineage,
membership/removal/reactivation/profile stale saves, missing token rejection,
standalone/unmarked/participant completed denial and exact other-target/history.
Blind identity rehide is CVA-tested; Legacy retains its existing supported Open-
only contract, so Blind Legacy is N/A and no mode expansion was introduced.

Fixture-only adaptations pass the getter's actual tasting token in
creator-active-completion-check, creator-sample-removal-check,
