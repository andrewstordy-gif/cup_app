## Acceptance criteria

- The guide clearly distinguishes durable Git/repository state from disposable Codex chat, subagent, worktree, dependency-cache, and unpushed local state.
- It explains that a remote Git repository plus separately managed credentials/secrets and environment prerequisites are required for recovery after total computer loss.
- It provides a safe clean-clone restart procedure and a procedure for inspecting an interrupted task without guessing its status.
- It requires the new Project Manager to read repository authorities in order, inspect current `main`, tasks, branches, PRs, tags, and tests, and report before changing anything.
- It preserves the single-interface Project Manager model, temporary implementation agents, independent review, and protected Release Manager merge path.
- It includes a self-contained copy-paste bootstrap prompt for a completely new agent.
- It explains that completed task records are history, active task status must be verified against Git/PR state, and chat claims alone are not authoritative.
- It warns that uncommitted, unpushed, ignored, or local-only work may be irrecoverable after deletion/device loss.
- It includes a short end-of-session checklist that improves recoverability without committing secrets or generated dependency directories.
- `AGENTS.md` and `README.md` link to the guide without duplicating or overriding the operating model.
- No product or production-code behaviour changes.

## Decisions

- The Git repository and its durable documentation are the recovery source of truth; Codex conversation history is helpful but non-authoritative.
- Recovery starts read-only and does not resume implementation until repository state and active tasks are reconciled.
