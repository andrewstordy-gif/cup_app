## Acceptance criteria

- The Product Specification states the PO-approved **0.00–10.00 inclusive in 0.25 steps** Cup App Legacy extension, distinguishes it from the 2009 protocol's explicitly listed 16 marks `6.00…9.75`, and keeps all other Legacy and CVA requirements unchanged.
- The new versioned Legacy definition accepts integer quarter-units **0…40** for each of the seven quality ratings; all seven remain required for completion. Values not on quarter marks, below 0, above 10, missing, malformed, or pinned to the wrong form identity fail explicitly. Existing score arithmetic and final two-decimal rounding apply to accepted values without clamping or inventing a minimum total.
- The earlier reviewed Legacy definition/hash is not mutated in place under the same version. The registry has exactly one active `f=2` triple for each protocol profile and never guesses from tag bytes. The task handoff documents what happens to existing internal v1 test Sessions, responses and physical `f=2` tags; no old record is silently promoted to the new form version.
- Pure result/export projections make an out-of-the-protocol-table quality mark (`0.00…5.75` or `10.00`) distinguishable from an ordinary listed mark; the exact user-facing wording receives UX review. Non-five-cup adapted labels remain present and independent of this range provenance.
- Contract tests cover 0.00, 5.75, 6.00, 9.75, 10.00, invalid quarter increments and bounds, all seven fields, score arithmetic, old-form mismatch, CVA regression, and canonical hash verification. Existing relevant tests pass. No claim of phone/NFC verification arises from pure tests.
- The mobile UI handoff specifies a paper-like ruler whose tap opens a large exact-value selector: show **6.00–10.00** initially; reveal **0.00–5.75** behind an explicit “Show lower scores” action. Mobile implementation belongs to an updated R1-010 task and requires device/UX review, not this pure-contract change.

## Decisions
