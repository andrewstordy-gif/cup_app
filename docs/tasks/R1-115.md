### Implementation design and handoff

- A nullable/no-backfill boundary is inherited from R1-114 enrollment. Only its
  stored creator, active targets and supported locked identity grant the new
  `kind:creator-tasting` removal permission. Confirmation token binds actor,
  target activation, durable removal generation, session revision/hash and recovery.
- Add `local_creator_sample_removals` keyed by session/creator/sample, retaining
  code/lock snapshot, monotonically increasing safe-integer generation and removal
  timestamp. The row persists across activation deletion/rescan and cascades only
  with actual sample/session deletion. Damaged identity/generation fails closed.
- `removeCreatorTastingSample` captures the command, verifies token/actor/current
  ownership and supported full roster, and atomically preserves history, reopens
  current status, clears target results/projections/recovery, deletes its activation,
  increments epoch and commits/recomputes local revision/status. No sample metadata,
  codes, ordering, issuer reservations, other sample or physical cup changes.
- CVA appends a validated canonical empty draft using the unchanged adapter in the
  same transaction. Old revisions remain historical; expectedRevision remains
  monotonic even for unscored/repeated blank removal, so old forms cannot resurrect.
  Legacy clears only its mutable current row/recovery; positive removal generation
  is included in its fingerprint. Generation0 retains exact predecessor fingerprint,
  preserving already-saved recovery without migration.
- Enrolled Legacy Save/recovery require `expectedRemovalGeneration`, returned by
  its getter and captured in the actual form enqueue command. Existing execution-
  time same-generation fingerprint advancement is preserved. Old queued work cannot
  borrow a later generation's fingerprint. Discard uses the generation-bound
  fingerprint. No changed behavior for unmarked/participant/QuickStart sessions.
- Creator-only current score status handles both forms: remaining actual saved
  ratings => IN PROGRESS; none => PENDING, without unlocking setup/history. Existing
  full-roster completion remains unchanged. A blank target cannot have valid
  full-roster completion; a scored removal changes semantic content and invalidates
  current completion evidence. Historical immutable completion events are retained.
- Details reuses existing card removal binding with approved **Remove Sample** /
  **Remove this sample from your cupping session.** and one neutral **REMOVE**.
  Cross/backdrop dismissal is nonmutating; participant warning remains unchanged.
- Before confirmed creator removal, optional `onLocalTastingRemovalStart` revokes
  existing Nav action token synchronously, gates new scans until removal settles,
  and removes just target cached selected/swipe contexts. Old native cleanup still
  releases busy/launch guards only after its read settles. Existing resolver
  `isScanCurrent` checks reject revoked activation callbacks; no transport changes.
