## Product Owner decisions to preserve exactly

Roles are per session, not permanent user types. One persistent local profile may createA and participateB. Local creator provenance derives from stored identity/ownership, never editable profile fields/NDEF/caller flags. Prior approved local-first stage exists in reviewed phone-spec R1-056/c16cdde but is not on main: read it for decision provenance and reconcile the approved scope, do not copy runtime/whole feature branches or waive later online/auth/encryption/production gates.

Creator new DRAFT can edit session name/type/form and coffee setup before assignment, add/edit/remove unassigned coffees/assign cups and Save without coffee; empty saved session stays DRAFT and visible. With coffee after Save ->PENDING. No assessment before Save. Once written to assigned cups, session name/type/form and coffee name/process are locked, including temporary DRAFT. Changes require physical cup removal then reassignment, not silent metadata edits. Creator may add coffee/remove cups while PENDING or IN PROGRESS, except after their tasting has once been COMPLETE (setup remains locked when subsequent tasting edits reopen it). Permitted setup edits ->DRAFT; preserve durable started history, prior scores and blind protection; successful Save restores PENDING if not started or IN PROGRESS if already started. Opening form alone does not start; first saved score OR note ->IN PROGRESS.

Blind creator expanded cards may show preparation metadata only before tasting starts; forms always hide until current completion. Once started hide coffee/process from all relevant app projections until explicit current completion. Complete Session requires required saved scores for every remaining local sample. Immediate clear warning if incomplete. Notes are not newly required. COMPLETE reveals locally. Saving actual score/note edits after completion ->IN PROGRESS AND hides details AND removes current-upload success indication; merely opening/typing unsaved edits does not change previous committed state. Leave/Stay warning on unsaved setup/form exit; ordinary Leave discards only uncommitted edits and retains prior saved state/COMPLETE when applicable. Crash-recovery draft storage is not explicit Save/commit or consent. This supersedes prior monotonic/permanent-reveal and host-global edit-lock implications; do not claim hiding makes already-seen information secret again. Current local completion is revision/coverage-specific, distinct from durable has-ever-started/has-ever-completed setup restrictions and distinct from service host-global lifecycle. Preserve historical data without silent provenance claim/recalculation/reveal or reset.

Participants have independent local copies and only see samples actually scanned/added, not an enumerated host roster; preserve assigned sample numbers. Scanning cup and pressing card open form; no setup controls. New scanned sample may be added while IN PROGRESS; scanning new sample after COMPLETE ->IN PROGRESS/hide/preserve existing scores. Existing sample rescan merely opens form. Participant Complete checks only their remaining scanned samples. Participant can remove local sample with warning for its saved scores/notes; no NFC/creator/other-device mutation. Removal after COMPLETE ->IN PROGRESS/hide; last-sample removal stays visible IN PROGRESS, Scan Cup available, cannot complete until another sample added/scored. COMPLETE same edit/reveal/upload rules as creator, but no creator authority.

Original Complete Session / Scan Cup footer at session level; no duplicate action above scores. COMPLETE keeps Scan Cup alongside original upload control BOTH roles. Assessment Save/Scan/notes/scores/CVA nine-score single-row untouched. No novel main controls. Session-list delete cross available ALL states BOTH roles. Whole-session deletion confirmed local-only, removes local records/results AND pending NFC verification AND cancels/deletes queued upload, never scans/rewrites cups or deletes creator/other-device/service already-uploaded results. Pending NFC exception latest owner decision: deliberate DELETE discards pending verification; ordinary Leave/crash preserves it. Warn specifically if upload pending. Distinguish mobile delete-local-copy from existing tenant/service-wide erasure/tombstone policy; do not weaken that service policy or imply remote erasure.

NFC: durably stage intended operation BEFORE any external write; if stage fails no cup change. Write, then separate physical RESCAN/read-back verifies cup identity + complete intended canonical data. Never claim write callback is verification. Keep DRAFT unfinished until verified + successful session Save; restore prior PENDING/IN PROGRESS. If cup write succeeds and final DB Save fails, keep previously durable recovery intent, retry existing Save idempotently/no duplicate/unnecessary rewrite. Leaving/restart before verification resumes RESCAN TO VERIFY, never automatic rewrite. Mismatch stays unfinished; no silent overwrite. Applies assignment/removal/reassignment. Full smart-cup preservation/NTAG contracts unchanged. Do not invent wire clearing bytes: exact unassignment and affected i/z/y counters consistency must be an explicit contract/conformance gate in NFC implementation plan, since dynamic samples and mandatory all-physical-cups consistency can conflict with cached tag totals. Existing assignment journal cancellation/rollback text must distinguish deliberate LOCAL DELETE (no tag write) from physical remove/reassign and ordinary Leave; do not accidentally retain forbidden post-delete callbacks/records.

Upload: ONLY press Upload (mobile label for existing Share results contract) authorises immutable completed-results snapshot; completion/save/connectivity cannot create consent. Offline press queues; return connectivity sends/retries original consented bytes. Existing queued snapshot continues eligible if current local results later edited/reopened; do NOT pause or cancel merely on edit. Changed results need Save ->complete again ->Upload. Replace them with your latest completed results? Yes, replace / No, keep existing". Yes creates new consent/snapshot operation/revision, supersedes unstarted queue where safe without mutating old immutable operation identity/bytes; No leaves old queue/remote version unchanged. Do not upload current unsaved/incomplete revision. Backend idempotent retries, latest revision supersedes older, late older cannot overwrite newer; preserve participant/session/tenant/stream scope, raw/audit and conflict requirements. Technical detailed ordering across device/stream is to be designed/tested, not invented as global wall-clock or cross-profile last-write-wins. Do not claim upload/backend currently works.

Status icons not buttons, accessible equivalent text. No icon if no pending upload/current revision ack. Queued old snapshot status distinct from current saved revision and upload button availability. Blue ONLY physical cup actions. Upload/action/status icons neutral grey, Save/Complete neutral.
