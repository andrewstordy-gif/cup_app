- A newly created prototype Session has an explicit pinned form identity from the R1-008 registry (`f=1`, CVA Affective key/version/hash). The host sees the form at Session level. This first slice may show Legacy as disabled with an honest explanation, or omit it until available; it must not let anyone create or write a Legacy session that opens the CVA screen. A required form value is never guessed from an unknown input.
- Adding or editing a sample cannot independently change the Session form. Every new sample inherits the pinned Session form for the existing CVA-only prototype path. The existing CVA screen and saved results remain usable for a new CVA session.

## Decisions

- The Product Specification already decides **one form per Session** and two Release 1 forms. The current per-sample picker and unknown-to-CVA fallback are prototype defects, not product policy.
- This task is intentionally CVA-only at the user-facing boundary because no Legacy capture/results path exists. Exposing a selectable Legacy option now would create false results. A subsequent bounded task must deliver the distinct Legacy form before `f=2` can be used in a user-testable build.
- The existing prototype database is disposable and plaintext. Any added Session form columns are prototype scaffolding, not the fresh encrypted Release 1 schema or a migration plan. Do not import or delete old records. Production-store readiness remains a separate gate.
- Preserve the established CVA look and interactions. Only move the form decision from the sample sheet to the Session context; no redesign of the Cupping screen.
- Independent entry review **PASS** on task commit `af0c618`: no new Product Owner decision needed. Implementation watchpoints: reject raw scanned NDEF `f` (including missing, malformed, or `2`) before any local-sample fallback can route to CVA; do not infer `f=1` from an old row. Once a Session form is pinned and a sample/tag write exists, conflicting changes must be blocked rather than rewriting the Session/tag association. Because the prototype writes tag metadata before saving the database transaction, interruption tests and the handoff must not claim atomic production NFC behaviour.
