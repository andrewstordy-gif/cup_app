Version1 canonical JSON stores immutable candidate, full intended save input, exact already-built metadata, baseline setup fingerprint. No scores/participant roster/network state. No row in samples before check. Existing sessions/scores unchanged.
- Stage inside existing asynchronous writer callback after target identity/payload/candidate are built, BEFORE returning unchanged writer bytes. Failure to persist prevents write. Treat staged write outcome as uncertain until physical re-scan; never automatically write on reload. Same-session retries keep candidate ID and target; changed details create new operation token before explicit write and invalidate older check. Other target/session conflicts fail closed. Existing radio calls, classification, serializers, state bytes, metadata builder/matcher and smart/NTAG records stay unchanged.
- Recovery: owner-authorised load retrieves journal separately from sample projection and restores fields via ADD SAMPLE (no Resume/Verify control). Closing either verification dialog retains journal/fields and reopens drawer; close drawer/ordinary leave retains intent. Reopen checks first rather than auto-writes, via existing physical check dialog after user opens retained drawer; no surprise write on entry.
- Final successful check: commit using existing saveSessionWithSamples normalization/guards inside ONE existing exclusive transaction that validates journal token/actor/baseline and exact intended input, writes membership, consumes journal atomically. Save failure retains journal. Stale/duplicate/deleted operation cannot recreate membership. No new alternate sample-write path.
- While a pending record exists, ordinary save/setup mutations and local assessment/import into that session fail closed to protect captured context; whole-session deletion remains available and cascades only local journal. Scope this guard to presence of journal; non-pending paths unchanged. Profile changes/deletion/changed membership reject stage/recovery/commit. Cross-session pending cup reserved before write.
- Duplicate-cup Add retains existing sample ID/position and does not update its membership/details before successful check; original committed membership stays intact, journal holds replacement candidate. Existing Edit Sample flow is not redesigned. Quick start remains same callback after successful verified commit, not before. First and later CVA/Legacy additions supported with existing form/mode restrictions unchanged.
- Modal closure/callback safety: invalidate current read/rewrite continuation on close; reject late callbacks. Atomic final commit phase cannot be dismissed midway. Busy-operation refs prevent double starts; safe iOS dismissal sequencing restores drawer via onDismiss, no stacked modal redesign. Preserve all other navigation/controls. No new NFC bytes for recovery.
