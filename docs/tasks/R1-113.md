## Handoff / review / DoD

### Approved implementation design (22 October)

PM approved two nullable additive session columns: `local_setup_locked_at` and
`local_setup_lock_snapshot`. No backfill; NULL/NULL preserves old-session
behaviour. Invalid or partial lock values fail closed. This boundary is separate
from form pinning and tasting history. Readiness is read-only and proves owned,
saved normal DRAFT, active form, nonempty verified membership and no durable
pending addition. Verification uses member metadata plus issuer/issued operation
and committed outcome records, not UI flags. The canonical saved-setup snapshot
excludes ratings, history and mutable update timestamps. The atomic command
rechecks actor, ownership, snapshot, DRAFT and pending work in its transaction,
then records the lock and PENDING together; the same stored snapshot is an
idempotent acknowledgement. Four setup mutation boundaries and setup projection
deny locked setup; tasting and whole-session deletion are not globally blocked.
The screen additionally requires a clean, idle saved normal DRAFT and fences the
confirmation against changed local input/session epoch. It uses WarningDialog,
does not scan, and refreshes the real projection in place after success.
