## Acceptance criteria

- A host can select **SCA CVA — Affective Assessment** or **SCA Legacy (2004–2023)** when creating a new Session. The selection pins exactly the active bundled numeric `f`, form key, version, and definition hash; Legacy means R1-011 v2, never v1. Existing Sessions do not silently change. Saving a new Session with only its required name and selected form is possible before a sample is assigned, in line with FR-010. Later samples inherit the Session form; form changes after any sample/tag/response are blocked. Existing unversioned or v1 prototype Sessions remain present but visibly unsupported/read-only rather than silently promoted, re-scored, or deleted.
- The first user-testable Legacy slice is explicitly **Open Cupping only**. Persist and trust a Session-level Open mode for `f=2` even before the first sample; do not infer it from a tag or a sample row. The UI and repository block a Legacy Blind Cupping assignment/scan path before writing a tag, importing a sample, or creating a response and explain the limitation. This temporary restriction is not a redefinition or completion of Release 1 blind requirements; a subsequent bounded task must implement safe blind projection before pilot readiness. Existing CVA mode choices must not regress.
- A new Legacy sample may use 1–8 physical cups. Its tag payload uses the unchanged canonical protocol with numeric `f=2`; a verified `f=2` scan opens a distinct Legacy screen only when the trusted local Session/Sample identity is the exact R1-011 v2 triple and the physical cup/assignment matches. Missing, malformed, conflicting, unsupported, historical, or cross-form values never open CVA or Legacy by guesswork. The host receives an actionable visible error for an already-assigned/conflicting cup, not a beep alone. Quick Cupping may remain CVA-only if plainly labelled and guarded. Do not change the physical NFC writer/serializer or claim hardware verification from tests alone.
- The Legacy screen captures all seven quality ratings as discrete R1-011 v2 quarter-point marks `0.00…10.00`, not CVA's 1–9 buttons. Use the approved compact overview and a paper-like ruler that opens an exact-value button selector: `6.00…10.00` initially, with `0.00…5.75` behind an explicit **Show lower scores** action. When revealed, the lower marks appear before `6.00` in the **same ascending score grid**, not in a second block after `10.00`. The selected ruler mark must be visibly darker using an existing style token. A selected low mark remains visible when the selector reopens; unset is not treated as 9.75 or any other score. Preserve consistent/sweet/clean judgments by individual cup with one-cup Uniformity fixed at 10; one scored taint or fault with description and affected-cup set; and all optional observations. The UI may group fields for table use but cannot omit or silently reinterpret a canonical field. Large accessible touch targets, labels, error states, keyboard handling, and the quiet established visual style are required.
- Draft edits persist locally without network access and survive a force-close/reopen. Store the immutable Session form identity, sample/cup count, exact raw Legacy judgments and explicit unassessed versus assessed-empty states; never store only a derived total. Use the R1-011 `validateResponse(input, trustedSession)` and `scoreResponse(input, trustedSession)` contract for completion and score projection. An incomplete/invalid draft has no final score and shows corrective validation without losing saved input. A historical v1 pin remains visibly read-only and is never reinterpreted under v2. The prototype persistence is not represented as the production protected store or complete FR-031/039 durability.
- A valid Legacy result displays the correct seven quality components, cup-wise component scores, single defect deduction (show `0.00`, never `−0.00`), final two-decimal score, and **“Adapted — five-cup-equivalent Cup App score”** on every non-five-cup total surface. Five-cup results are not labelled adapted. Values outside the protocol's printed `6.00…9.75` table carry the R1-011 Cup App extension explanation near the result. Reopening the Session or rescanning the same cup restores the same response and result, not a duplicate or a CVA result. Completed results have a clear read-only state rather than a misleading **COMPLETE & SCORE** action. Session completion/summary must not present Legacy data in CVA score boxes or silently calculate a CVA score. Assigned Legacy samples use an established sample presentation rather than a bare row.
- Focused automated tests cover both Session choices, empty-Session save, `f=2` and unsupported scan routes, immutable/mismatched v1/v2 form identity, 0.00/5.75/6.00/9.75/10.00 marks, lower-score reveal/selection, no implicit default, 1/3/5/8-cup Legacy responses and adapted labels, incomplete draft and exact numeric score fixtures, result provenance, persistence/reopen, single scored defect, mode restriction before tag write, cup-conflict messaging, completed read-only state, and CVA regression. Relevant existing form-contract, identifier, virtual NFC, and routing tests plus an iOS development bundle pass. Human iPhone testing of form usability, app restart, and physical `f=2` write/read-back/scan is required before calling this a device-verified increment; record exact device/tag/firmware evidence or explicit limits.
