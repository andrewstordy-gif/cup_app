## Acceptance criteria

- Release 1 consistently supports exactly two forms: SCA CVA and SCA Legacy 2004–2023.
- The canonical NDEF4 mapping is `f=1` for SCA CVA and `f=2` for SCA Legacy 2004–2023, with no existing repository collision and no value assigned to later forms.
- Quick QC and Purchasing/selection are moved to subsequent-release scope and removed from Release 1 UI, acceptance, validation, and pilot claims without deleting their longer-term product rationale.
- FR-028B is updated from unresolved blocker to an approved two-form Release 1 mapping; stale blocker warnings are removed from all affected authorities and operating guidance.
- Unknown or unsupported `f` values fail visibly and are never guessed or silently mapped to SCA CVA.
- The architecture still requires one immutable bundled `(form_key, form_version, form-definition hash)` per supported NDEF value.
- Pre-release prototype data is explicitly disposable. Release 1 creates a fresh encrypted database and does not require a legacy importer, mapping ledger, rollback database, or user-facing prototype migration flow.
- Forward schema migrations, durable storage, rollback/recovery, deletion handling, and compatibility remain mandatory from the first Release 1 production schema onward.
- No existing device data is deleted by this documentation task.
- Release 1 online capabilities are required to be reliably accessible from mainland China without mandatory Google-hosted dependencies.
- Mainland-China physical hosting is explicitly not required for Release 1; provider selection must assess real mainland-China reachability, latency, reliability, and all transitive dependencies.
- The China requirement covers host authentication, session access/reconciliation, explicit result sharing, the host portal, exports/downloads, and operational dependencies; offline cupping remains independent of connectivity.
- README and operating-model statements are descriptive and consistent with the higher authorities.
- Existing blind-reveal, explicit-share, offline, privacy, and NFC write/read-back requirements remain unchanged.

## Decisions

- Product Owner approved SCA CVA as `f=1` and SCA Legacy 2004–2023 as `f=2` for Release 1.
- Quick QC and Purchasing/selection may be added in subsequent releases; their NDEF values remain unassigned.
- Existing prototype data need not be retained. Release 1 may start from a clean database; this task does not authorise or perform deletion.
- Release 1 must be accessible from mainland China without mandatory Google dependencies, but does not require infrastructure physically hosted in mainland China.
