## [2026-06-24] — Codex

- `scripts/virtual-nfc-robustness-check.js`: updated the metadata verification check so legacy sample-colour differences are treated as ignored, matching the new sample-colour-free cup metadata contract.
- `app.json`: linked the app to the new EAS project `@andrewstordy/cup` so production iOS builds can be submitted through the EAS/TestFlight path.
- `README.md`: documented the TestFlight release account guardrail: use Apple ID `andrewstordy@gmail.com`, do not use the cached `andrew@ikawacoffee.com` session, and stop if EAS/App Store Connect routes the release through IKAWA LTD.

## [2026-06-21] — Claude Code

- `src/navigation/AppNavigator.js`: fixed scanning a reset-to-OFF NTAG incorrectly showing "This session is already complete" instead of the sleep/choice dialog. The `isNtagCupLike` branch of `scanCupForAssessment` (covering `NTAG_CUP`/`GENERIC_NDEF_TAG`/`EMPTY_TAG` classifications) never checked the cup's own reported `text1.state` at all — it went straight to looking up the physical tag's hardware ID via `findActiveSampleByCupUUID`. Resetting a cup to OFF only blanks its NDEF content; it doesn't delete the database row linking that tag ID to its old sample, so a reset NTAG that was previously used in a now-complete session was still found by ID and treated as belonging to that complete session, regardless of its own state. Added the same `cupState === 0` sleeping check the "regular" (non-NTAG-classified) branch already had, before any database lookup runs.
- `src/navigation/AppNavigator.js`: fixed `CuppingScreen` opening with only Fragrance enabled for NTAG-cup samples reopened via tap/swipe/quick-start (instead of all fields, per user request — NTAGs have no real state machine, so the cup itself "does not know what state it is in"). `CuppingScreen` already has an `isNtagCup` check that opens every field, but it only becomes true when `tagType` is known from a live scan in the current app session (via `sampleRuntimeById`); `buildContextFromSessionSample` — used by every non-live-scan entry point — previously defaulted `tagType` to `null` when that runtime memory wasn't available, falling through to the smart-cup state-gated logic instead. Defaulted it to `NFC_TAG_TYPES.NTAG_CUP` instead, since none of this function's callers represent a live scan anyway and there's no persisted way to know a sample's actual hardware type without one.

- `src/navigation/AppNavigator.js`: fixed the Quick Cupping flow opening `CuppingScreen` with both Fragrance and Aroma enabled, instead of Fragrance only like a genuine fresh scan would. `buildContextFromSessionSample` always hardcoded `cupStateNumber: 3` (CUPPING) since none of its other callers represent a live scan — but the quick-cupping completion moment is effectively equivalent to one, since the cup was just written. Added optional `cupStateNumber`/`cupStatus` overrides to `buildContextFromSessionSample` (defaulting to the existing behaviour for every other caller), and `handleQuickStartSampleReady` now passes `cupStateNumber: 1` / `state: "READY"`, matching what a real fresh scan of that same cup would produce.
- `src/navigation/AppNavigator.js`: unified the "Cup Not in Session" dialog (shown when a plain NTAG cup with no recognised session metadata is scanned) with the sleep-state cup choice dialog, per user request. Its "Use without session" button (which wrote `sessionUUID: "NO-SESSION"` to the cup, the same no-session mode being phased out) is now "Quick cupping", reusing `handleStartQuickCuppingFromSleepDialog` directly — it already resets both dialogs' visibility, so no new handler was needed. Removed the now-unused `handleUseWithoutSessionFromNotInSessionDialog`. Applied the same `variant="cupping-choice"` styling (charcoal "Add cup to session", grey "Quick cupping") for visual consistency between the two dialogs.

- `src/features/cupping/screens/CuppingSessionDetailsScreen.js`: hid the "ADD SAMPLE" button and each sample card's pencil edit icon while the session's derived status is "In Progress" (reusing the existing `showInProgressFooter` flag), per user request. Draft, Pending, and Complete states are unaffected — `onEditSample` is passed as `undefined` for In Progress (which `CoffeeSampleCard` already treats as "no pencil icon"), and "ADD SAMPLE" is now also gated on `!showInProgressFooter` alongside its existing `!isSessionComplete` check.
- `src/services/nfcServiceMinimal.js`: fixed `m` (cupping mode) and `f` (cupping form) being silently dropped from every NDEF text4 write. `compactText4Payload` is a separate, lower-level allowlist that actually shapes what gets serialized to the physical tag, distinct from `buildCompactSessionMetadata` (which already built `m`/`f` correctly) — the Codex change that added these two fields updated the latter but missed this one, so the keys never reached the cup despite the JS object correctly containing them. Added the same two fields to `compactText4Payload`'s allowlist. The read-side counterpart (`normalizeText4Payload`) was already non-lossy (it spreads `...payload` first), so no fix was needed there.
- `src/features/cupping/screens/CuppingSessionDetailsScreen.js` and `src/features/cupping/components/AddCoffeeSampleSheet.js`: the Add/Edit Sample sheet's "Cupping Mode" field now shows blue placeholder text reading "Select cupping mode" until explicitly chosen, then switches to the real selected label — mirroring the existing "Number of Cups" default-flag pattern, since `cuppingMode` defaults to `"blind"` (a real, always-truthy label), so a simple "label is empty" check never showed a placeholder before.
- `src/components/ui/WarningDialog.js`: added optional `secondaryButtonStyle`/`secondaryButtonTextStyle`/`okButtonStyle`/`okButtonTextStyle` props, so individual `variant="cupping-choice"` dialogs can override the default blue/dark button colours without affecting other dialogs using the same shared component (e.g. the newly-added "session already complete" choice dialog keeps its blue/dark colours unchanged). `src/navigation/AppNavigator.js`: the sleep-state cup choice dialog's buttons now match the style guide's documented examples exactly — "Add cup to session" is charcoal with white text (`colors.ink`, same as the style guide's "Save" button), "Quick cupping" is grey with charcoal text (`colors.muted`/`colors.ink`, same as the style guide's "Add Aroma" button) — per user correction after an initial attempt used grey for both.

- `KeywordPillRow.js` gains an `outline` prop: when true, pills render as a grey border with `colors.ink` text and no fill, for use in the cupping form during tasting to avoid influencing flavour perception.
- `CuppingScreen.js`: live grey-outline pill row now appears below each notes box, derived from current text as the user types. Pills show `temp|keyword` label when the observation has been previously saved. Removed `buildLatestObservationLabelsByKeyword` (unused).
- `ActiveSessionScreen.js` expanded drawer: reverted to plain notes text with a coloured `KeywordPillRow` below (with `temp|keyword` labels from stored observations). Removed `InlineNotesWithPills`, `buildKeywordLabelOverrides`, `KeywordTokenPreview` import, and `tokenizeFlavourKeywords` import.
- `sessionRepository.js`: added `pruneSampleFlavourObservations` — deletes stored observations whose keyword no longer appears in the notes text. Called from `CuppingScreen.handleSave` so removing a keyword from notes and saving removes its pill from the active session.

### Active Session screen improvements
- Expanded drawer redesigned: Coffee/Process on white surface, separated from notes sections by a thin divider; Fragrance/Aroma Notes and Flavour Notes each in a grey input-style box (matching cupping form style) with coloured pills below.
- Defect icons moved to appear after the score summary text (below "Current score X.XX" / "Score pending").
- Screen auto-scrolls to bring the expanded sample row to the top when a drawer is opened.
- `Header` gains a `hideBack` prop — when true the back arrow is hidden while keeping the header layout intact. Used in `ActiveSessionScreen` (hidden when any sample is expanded) and `CuppingScreen` (hidden when defects drawer is open) to prevent accidental back navigation.

### Three session state screens (Pending / Active / Complete)
- Added `active` as a new session status between `pending` and `complete`.
- DB migration: sessions that have any feedback data but are still `pending` are automatically migrated to `active`.
- `resolveActiveSampleFromCupMetadata` now transitions a session from `pending` → `active` the first time one of its cups is scanned.
- `markSessionCompleteIfAllSamplesComplete` now restores sessions to `active` (not `pending`) when a previously complete session is edited.
- New `sessionRepository` exports: `activateSession`, `manuallyMarkSessionComplete`, `getSessionCompletionSummary`, `deleteSampleFromSession`.
- `ActiveSessionScreen` gains a `mode` prop (`pending` / `active` / `complete`) that controls titles, footer actions, and editability:
  - **Pending**: header "Pending Session", footer "EDIT SESSION" → `CuppingSessionDetailsScreen`.
  - **Active**: header "Active Session", footer "SCAN CUP" + "MARK COMPLETE". Tapping "Mark Complete" checks completion; if any sample is missing scores a dialog lists them. If all complete the session is marked complete and the user returns to the session list.
  - **Complete**: header "Session Review", no footer. Read-only.
- Sample delete button (×) shown on each cup row in pending and active modes. Tapping removes the sample and reloads the list.
- `CuppingSessionScreen` now routes session list taps to the appropriate screen based on status (Pending/Active/Complete Session).
- `CuppingScreen` gains an `isSessionComplete` prop; when true all inputs are locked (read-only review).
- Back button from `CuppingScreen` now always returns to Home.

### Active Session — defects summary in expanded drawer
- Added read-only defects summary below the notes sections when a sample row is expanded.
- Cup circles (46×46 scaled, fully circular) show highlighted slots for any non-uniform or defective cups.
- Bean defect pills and roast defect pills appear below the circles, matching the style from the cupping defects drawer (panel background, quiet border, icon + label).
- Summary section is hidden entirely when no defects are recorded.

### Cupping Session screen
- Full style guide alignment: all hardcoded hex colours replaced with `colors` tokens; all hardcoded font sizes replaced with `typography` tokens.
- `FloatingActionButton` replaced with standard fixed-footer `FullPageButton` ("NEW SESSION", charcoal).
- `ScreenContainer` replaced with plain `ScrollView` using `spacing.lg` (24) horizontal padding.
- Session status (Complete/Pending) displayed as plain `text_secondary_body` text on its own line.
- Filter row (session type filter chips) removed — not needed.
- Empty/error state simplified to centred text without a border card.
